# AI Automation Portfolio Architecture

This repository intentionally follows the same family pattern as Brianna Dickenson's other professional portfolios: a lightweight `site/` portfolio shell plus separate top-level project folders.

## Shared Portfolio-Family Rules

- Light editorial visual system
- Georgia-style display headings + clean sans-serif body typography
- Rounded cards, pills, and buttons
- Similar max-width, hero proportions, section spacing, and contact treatment
- `🎀 Brianna Dickenson` identity
- Role-specific accent palette and hero visual
- Portfolio Family section near the bottom
- Specialty-focused navigation in the header

## AI Automation Specialty Rules

- Accent palette: lavender + periwinkle
- Visual language: workflows, connected nodes, architecture maps, metrics, audit/status UI
- Primary employment CTA: **Seeking Full-Time Remote Position**
- No freelance pricing or service packages
- Four flagship systems because each intentionally covers a different skill area
- Project cards lead to case studies before live demos/source

## Project Case-Study Standard

Every case study should answer, in order:

1. **Before** — What did the manual process look like?
2. **Automation** — Which steps changed and why?
3. **Architecture** — How do services, models, workflows, data, and people interact?
4. **Human Review** — Where does judgment remain intentionally human?
5. **Reliability** — What happens when data, models, or APIs fail?
6. **Evaluation** — How is the system tested?
7. **Results** — What measurable change occurred?
8. **Demo / Source** — Can a reviewer inspect the working system and implementation?

## Truthfulness Rule

Never present synthetic benchmarks, test datasets, or projected savings as client production results. Label them clearly as **benchmark**, **simulated**, or **projected** until genuine production data exists.

## Build Rule

Projects are implemented one at a time. Planned project folders can exist for portfolio architecture, but only completed functionality is described as completed functionality.
